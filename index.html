How it works

A simple chain of accountability

1 Create

Capture the record

The document, content block, report, code output or decision record is assigned an AIRPP manifest ID.

2 Record

Log AI involvement

The manifest records the model/tool involvement level, source material and generation events.

3 Review

Attach human judgement

Review events show who checked the output, what was changed, and whether responsibility was accepted.

4 Verify

Export and validate

The manifest can be validated in-browser today and later through a live API or MCP server.

Technical specification

AIRPP v0.3 Public Draft

A lightweight, implementation-first specification for portable AI record provenance. This page is deliberately written for vendors, auditors, technical teams and governance reviewers.

Open-source initiative JSON manifest No API required for basic use
OverviewData modelConformanceIntegrityMCP / API pathRoadmap

Purpose

AIRPP defines a portable provenance layer for AI-assisted records. It does not attempt to certify truth by itself. It records the lineage, human accountability and verification state of a record so that another person, organisation or system can understand how the record came into existence.

Record

A document, report, code artefact, decision note, image description, policy draft, financial schedule or other output.

Manifest

A structured JSON file that travels alongside the record and describes AI involvement, actors, sources and review state.

Verifier

A tool, page or service that checks whether the manifest meets AIRPP requirements.

Core data model

The minimum useful AIRPP manifest has seven core areas: version, manifest identity, record metadata, AI involvement, actors, timestamps and conformance level.

{
  "airpp_version": "0.3.0",
  "manifest_id": "airpp-mf-demo-001",
  "conformance_level": "basic",
  "created_at": "2026-04-28T12:00:00Z",
  "record": { "record_id": "rec-001", "title": "Example record" },
  "ai_involvement": { "level": "language_assist", "human_final_responsibility": true },
  "actors": [{ "actor_type": "human", "role": "author_and_reviewer" }]
}
ObjectRoleExamples
recordDescribes the thing being protected by provenance.Report, article, R&D narrative, board paper, code review.
ai_involvementExplains how AI was used and whether a human accepts final responsibility.Drafting, summarisation, language assistance, generation.
actorsIdentifies human, organisation and AI participants.Author, reviewer, vendor, model provider.
sourcesOptional but recommended source trail.Documents, transcripts, datasets, web pages, repositories.

Conformance levels

Basic

Minimum manifest

Required fields, at least one human actor and explicit human final responsibility.

Auditable

Full provenance trail

Includes sources, generation events, content blocks, review events and integrity hash.

High Assurance

Signed and controlled

Includes reviewer attestation, event chain, package hash and stricter role controls.

Integrity and verification

AIRPP verification starts with structure. A verifier checks whether required fields exist, whether actors and responsibility are present, and whether the manifest is coherent. Later versions can add canonical hashes, signed attestations, C2PA bridges and W3C PROV mappings.

  • Canonical manifest hashing using SHA-256.
  • Optional package hash covering both record and manifest.
  • Review events that identify human sign-off and outcome.
  • Extension fields for regulated sectors, code provenance and evidence bundles.

MCP and API path

The project can operate without an API during early testing. The natural next layer is an API service exposing validation, registry and manifest submission endpoints, followed by an MCP server for provenance capture inside AI-enabled workflows.

GET  /api/health
POST /api/validate
GET  /api/registry
POST /api/manifests
POST /api/review-events

Certification model

Certification should remain lightweight at first. The early model should not become a bureaucratic badge factory. It should simply ask: does the implementation generate valid manifests, make AI involvement visible, preserve human responsibility, and allow exports that another system can inspect?

Stage 1

Self-declared adoption

Organisation states it is testing or using AIRPP.

Stage 2

Validated implementation

Sample manifests pass AIRPP conformance checks.

Stage 3

Certified partner

Implementation review, public listing and ongoing version commitments.
