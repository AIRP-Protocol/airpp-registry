Technical Specification

AIRPP v0.2.0 Public Draft

Frozen for implementation testing. Open, vendor-neutral, machine-readable provenance for AI-assisted records.

frozen_public_draft v0.2.0 JSON Schema 2020-12
Overview Schema Conformance levels Manifest structure Extensions MCP binding

Overview

AIRPP (AI Record Provenance Protocol) is an open, vendor-neutral protocol that defines how to attach structured provenance metadata to AI-assisted records. It specifies who created a record, which AI systems were involved, which sources were used, what human reviews took place, and how the integrity of the record can be verified.

Design principles

AIRPP is designed to be minimal, composable and interoperable. The core schema captures the provenance chain of a record without mandating a particular AI system, workflow tool, or delivery mechanism. Extensions allow domain-specific enrichment without breaking core conformance.

Protocol status

AIRPP v0.2.0 is a frozen public draft. The schema is stable for implementation testing. Extensions are in draft status. The registry is open for self-registration.

Schema

AIRPP manifests are JSON documents validated against the AIRPP JSON Schema 2020-12. The schema is hosted at the registry and versioned with each protocol release.

Required fields

// Minimum valid AIRPP v0.2.0 manifest (basic conformance) { "airpp_version": "0.2.0", "manifest_id": "airpp-mf-abc123", "conformance_level": "basic", "created_at": "2026-04-26T09:00:00Z", "record": { "record_id": "rec-001", "title": "My AI-assisted document", "output_type": "general_document", "language": "en-GB", "created_at": "2026-04-26T09:00:00Z", "current_version": "1.0.0" }, "ai_involvement": { "level": "language_assist", "human_final_responsibility": true, "summary": "AI was used to improve clarity." }, "actors": [ { "actor_id": "actor-human-001", "actor_type": "human", "display_name": "Responsible Author", "role": "author_and_reviewer" } ] }

Conformance levels

AIRPP defines three conformance levels. Each builds on the previous.

Basic

Basic

Minimum valid manifest with required fields and at least one accountable human actor.

  • Schema valid
  • Accountable actor present
  • Record metadata
Auditable

Auditable

Full provenance chain: content blocks, sources, generation events, reviews, exports and integrity hash.

  • All Basic requirements
  • Content blocks and sources
  • Generation events with prompt records
  • Review events
  • Integrity hash
High Assurance

High Assurance

Event chain, package hash, and at least one signed reviewer attestation. Suitable for regulated environments.

  • All Auditable requirements
  • Event chain metadata
  • Package/export hash
  • Signed attestation

Manifest structure

An AIRPP manifest is a self-describing JSON document. Key sections:

record

Metadata about the output: title, type, language, version, intended use.

actors

Human and AI participants: author, reviewer, AI service, organisation.

sources

Documents, repositories, APIs and databases used as AI context.

content_blocks

Sections or blocks of the output with AI involvement level and verification status.

generation_events

When and how AI generated content, with model details and prompt records.

review_events

Human review steps with outcome, reviewer identity, and optional attestation.

integrity

SHA-256 canonical manifest hash, signature status, and optional event chain.

extensions

Domain-specific fields: code provenance, attestations, regulated tax, legal, W3C PROV, C2PA.

Extensions

AIRPP extensions add domain-specific fields without breaking core conformance. All extensions are in draft status.

airpp-code

Code provenance: commits, branches, pull requests, files changed, CI tests.

draft

airpp-attestation

Signed attestations with signature algorithm and verification metadata.

draft

airpp-reg-tax

Regulated tax context: HMRC/DSIT alignment, scheme type, claim period fields.

draft

airpp-legal

Legal document provenance: jurisdiction, matter references, privilege flags.

draft

airpp-prov-mapping

W3C PROV ontology mapping for interoperability with existing provenance standards.

draft

airpp-c2pa-bridge

C2PA coalition for content authenticity bridge for media provenance interoperability.

draft

MCP binding

AIRPP provides a formal Model Context Protocol (MCP) server that exposes provenance capture as MCP tools. Any MCP-compatible AI host can automatically capture structured provenance without changing the user workflow.

Available tools

airpp_start_manifestStart a provenance session
airpp_record_sourceRecord a source used as AI context
airpp_record_generationRecord an AI generation event
airpp_record_reviewRecord a human review step
airpp_finalise_manifestHash, validate and store the manifest
